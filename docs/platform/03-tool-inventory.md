# Tool inventory

Generated by `forge-worker catalog` + `scripts/tool-inventory/render.py` from the live registry (`Engine::shared` with the AI and setup layer tools). Do not edit by hand.

- **326 tools**: 305 engine tools + 21 AI/setup layer tools.
- Need consent at dispatch (`EXECUTES_FOREIGN_CODE` or `MUTATES_DEVICE`): 29.
- Pure read-only (`IDEMPOTENT` only): 29.
- Available on this audit host with default settings: 98. Reasons for the rest: 215x This looks inside the original (its code, files or page source), which Clean room never does; 10x This needs Android platform tools (adb) installed; 2x This needs macOS or Windows and is not available on this host (linux-x86_64); 1x Nothing is open yet. Default settings run in Clean room mode, which refuses tools that read a target's code, files or page source until Deep mode is enabled. The `Here` column reflects that.

Proposed hosted-mode policy counts: approval gate: 14, editor: 194, editor, sandboxed worker: 42, operator-only: 13, unavailable (desktop OS): 3, unavailable (needs local device): 32, viewer: 28.

## Columns

- **Effects**: the tool's declared `Effects` bitflags (`crates/engine/src/tool.rs`). Abbreviations: `sess`=MUTATES_SESSION, `target`=MUTATES_TARGET, `fs-write`=WRITES_FILESYSTEM, `process`=LAUNCHES_PROCESS, `network`=ACCESSES_NETWORK, `ui`=CHANGES_UI_STATE, `discard`=MAY_DISCARD_DATA, `foreign-code`=EXECUTES_FOREIGN_CODE, `device`=MUTATES_DEVICE, `idem`=IDEMPOTENT, `target-content`=CARRIES_TARGET_CONTENT.
- **Requires**: `nothing`, `target` (an open target), `deep_engine` (Deep mode engine), `engine:<id>` (external program), `os:<list>`.
- **Mode**: `sync` = in-process work, expected to finish in a request; `job` = launches a process or uses the network, so the API runs it as a queued job with streamed progress. Measured durations are not recorded yet; the Phase 5 adapter will collect them per call.
- **Policy**: proposed permission in the hosted platform: `viewer`, `editor`, `editor, sandboxed worker`, `approval gate` (human approval, then `Consent::Granted`), `operator-only`, or `unavailable`.
- **Output**: every tool returns `ToolOutput` (`kind: evidence` with the full evidence record, or `kind: value`). The engine defines no per-tool output schema; the evidence record schema is shared (`crates/evidence`).
- **Input schema**: full JSON Schemas are in `tool-inventory.json` next to this file.
- **Test status**: all engine crates' unit tests were run during the audit (see 00-audit-report.md). Per-tool live verification from upstream is in `docs/tool-status.md`. No tool has been exercised through the platform API yet.
